Por que versionar

Você já viveu isso.

tela_home.figtela_home_v2.figtela_home_v2_FINAL.figtela_home_final_agora_vai.figtela_home_final_LUCAS_revisado.fig

O histórico de versões do Figma resolve parte disso. O git faz o mesmo para qualquer arquivo do projeto (código, docs, decks) e ainda permite que duas pessoas trabalhem em paralelo sem sobrescrever uma à outra.

Conceito 1

Repositório

A pasta do projeto + todo o histórico de mudanças dela. Existe uma cópia no seu computador (local) e uma no GitHub (remoto).

# baixar o repositório pela primeira vez
$ git clone https://github.com/<owner>/trama.git
$ cd trama

Conceito 2

Commit

Um "salvamento" com descrição. Cada commit vira um ponto no histórico, e dá para voltar a qualquer um deles.

Na Trama, mensagens em inglês, no padrão Conventional Commits.

$ git add management/vision/brief.md
$ git commit -m "docs: add first project brief"

Conceito 3

A main é a linha oficial.

A sequência de commits forma o histórico. A branch main é a versão oficial do projeto: o que está nela vai para o ar. Olhe a linha aqui embaixo, ela vai contar a história deste deck.

$ git log --oneline
c3 docs: add research plan
c2 docs: add first project brief
c1 chore: initial structure

Conceito 4

Branch: uma linha paralela.

Uma branch é uma cópia da linha principal onde você trabalha à vontade. A main não muda até você pedir para juntar (merge). É como duplicar uma página do Figma para explorar, só que dá para juntar de volta de forma controlada.

Segurança

A main continua estável enquanto você experimenta.

Paralelismo

Camille e Lucas trabalham ao mesmo tempo sem conflito.

Revisão

Toda mudança passa por um PR antes de entrar.

Na prática

Criar e trocar de branch

Sempre parta da main atualizada. Depois, trabalhe e faça commits normalmente.

$ git switch main
$ git pull
$ git switch -c feat/screen-upload
# ...trabalho...
$ git commit -m "feat: add upload area"

Conceito 6

Review

Primeiro um agente de AI revisa o diff. Depois a outra pessoa designer lê, comenta e aprova. Sem aprovação, a main não aceita o merge. Exceção: a admin pode fazer o merge sem aprovação para não travar o time.

Conceito 7

Squash & merge

Os commits do PR viram um commit na main. O histórico fica limpo, a branch pode ser apagada e o GitHub publica a nova versão sozinho.

feat: add screen upload (#13)
merged into main

Quando dá ruim

Conflitos

Acontece quando duas branches mudam a mesma linha do mesmo arquivo. O git não adivinha qual vale e pede para você escolher.

Dica: peça ajuda ao agente de AI ("resolva o conflito mantendo as duas mudanças"), mas confira o resultado antes do commit.

<<<<<<< HEAD
--color-accent: #C2603F;
=======
--color-accent: #B85A3A;
>>>>>>> design/color-tokens

AI no fluxo

Agentes de AI, qualquer um.

Um agente (Claude Code, Codex, Cursor, Gemini CLI…) lê e altera o repositório a partir de pedidos em linguagem natural. A Trama é agnóstica: as regras ficam num arquivo que qualquer agente entende.

AGENTS.md

Fonte única de instruções

Convenções, idioma, esteira e mapa do repo. Formato aberto: agents.md.

CLAUDE.md Claude-only

Ponte para o Claude Code

Só importa o AGENTS.md (@AGENTS.md) e adiciona o que é específico do Claude.

Skills: procedimentos reutilizáveis

Uma skill é um passo a passo num SKILL.md (formato aberto Agent Skills). Em vez de explicar tudo de novo, você pede: "registre essa decisão".

record-decision

Cria ADR/DDR e fecha a questão aberta.

open-pr

publish-artifact

Publicar artefato

Ficam em .claude/skills/. Se outro agente não ler essa pasta, dá para pedir que ele leia o arquivo como instrução.

Boas práticas

A AI propõe. A gente decide.

  • Leia o diff antes de commitar. Sempre.
  • Peça fontes e marque o que é sugestão e o que é fato.
  • Nunca cole chaves, senhas ou dados pessoais num prompt ou no código.
  • Mudanças pequenas e PRs pequenos são mais fáceis de revisar.
  • Não sabe? Abra uma questão aberta em vez de inventar.

Para ter à mão

$ git switch main && git pull   # atualizar

$ git status                      # o que mudou?

$ git push -u origin HEAD         # enviar
$ gh pr create                    # abrir PR
$ gh pr checkout 13               # revisar PR
