## Discussão
- **Repositório como fonte da verdade.** A Camille apresentou a estrutura (`management/`, `design/`, `ai/`, `app/`, `site/`), no modelo de fluxo que ela usa na Neon. O GitHub Projects substitui o Trello e o Figma passa a ter papel menor: a AI apoia pesquisa e prototipagem. Stack inicial: Vite + React ([ADR-0001](../decisions/ADR-0001-product-stack.md)), com possibilidade de reavaliação.
- **Figma.** Contas pessoais não entram num mesmo plano pago sem custo extra. Para contornar, a Camille criou um espaço gratuito (limite de 3 páginas) para rascunhos.
- **Esteira e Git.** Fluxo issue → branch → commits → PR → squash merge → deploy no Pages ([ADR-0004](../decisions/ADR-0004-git-workflow.md)). A `main` é protegida. O board se atualiza automaticamente com a abertura e o fechamento dos PRs. O Lucas comentou que o Git em linguagem natural, via AI, evita o terminal e as chaves SSH.
- **Revisão de PR.** O GitHub não tem pré-visualização ao vivo. Para mudanças visuais é preciso rodar o site ou o app localmente. Para um MVP sem usuários, revisar código e documentação pode bastar ([ADR-0014](../decisions/ADR-0014-pr-review-local-testing.md)). A Camille recomendou PRs pequenos e reforçou a revisão humana para pegar alucinações dos modelos, além de nunca subir senhas ou credenciais (o repositório é público).
- **Bypass de admin.** Com o Lucas no time, o bypass de admin passa a valer só para emergências ([ADR-0013](../decisions/ADR-0013-admin-bypass-emergencies-only.md)).
- **AI.** O projeto continua agnóstico de modelo, com o Claude como agente principal ([ADR-0003](../decisions/ADR-0003-ai-agnostic-strategy.md), [ADR-0011](../decisions/ADR-0011-claude-primary-agent-model-agnostic.md)). Falamos de compatibilidade das skills com outros agentes, como o Gemini ([OQ-012](../open-questions.md)), e do custo de tokens em planos Enterprise. Para o Lucas, a velocidade e a qualidade das entregas compensam o custo.
- **Idioma.** Documentação e contexto em português; código, pastas e termos técnicos em inglês ([ADR-0005](../decisions/ADR-0005-language-policy.md)).
- **Comunicação.** O Lucas sugeriu canais temáticos no Slack. A Camille argumentou que, no ambiente corporativo, o time não deve criar canais novos, então a comunicação vai por threads na DM ([ADR-0012](../decisions/ADR-0012-async-communication-slack-threads.md)).
- **Questões abertas.** Pendências ficam em [`open-questions.md`](../open-questions.md), resolvidas de forma síncrona (weekly) ou assíncrona. O agente lê o repositório inteiro, incluindo `management/`.
- **Cronograma e portfólio.** O time adotou o cronograma sugerido ([ADR-0010](../decisions/ADR-0010-project-schedule.md)). A documentação versionada (decisões, atas) também serve para mostrar o processo de design no portfólio.
- **Discovery.** As tarefas do Marco 1 saíram de um modelo (suposições, desk research, benchmark de AI, fontes de dados, roteiro de entrevista, termo de consentimento etc.). Tarefas que não fizerem sentido, como survey ou proto-personas, podem ser adaptadas ou encerradas ao longo do caminho. O Lucas lembrou que o tipo de pesquisa muda conforme o ciclo de vida do produto.
- **GitHub Desktop.** A Camille mostrou como clonar o repositório e fazer fetch/push pelo GitHub Desktop ([ADR-0015](../decisions/ADR-0015-github-desktop-git-client.md)).
- **Prototipagem Figma × código.** O MCP do Figma consome muitos tokens. O Lucas sugeriu definir um design system antes e alinhar os nomes de camadas, para que a AI leia o código. A Camille ponderou que as sugestões da AI trazem ideias que se perderiam com a interface toda pré-desenhada. O tema fica para testar e avaliar ([OQ-013](../open-questions.md)).
- **Contexto pessoal.** Troca sobre as trajetórias profissionais da dupla. Sem decisões.
